# Local development machine server

Use `node scripts/ops/local-server.mjs restart` to restart the pinned local
installation, and `node scripts/ops/local-server.mjs status` to verify it.
The private machine configuration is `.tools/local-server.json`. It records the
original database, server and relay container names, exact storage mounts,
installation ID, identity folder and origin. Keep this file with the local
operator records. Container names alone, matching installation IDs and matching
certificates are insufficient: restored copies can have divergent histories.

`restore` stops the listed competing stacks and this checkout's web Vite process,
then brings the pinned stack back to its enrolled address. It retains every
database volume and identity folder; it never recreates a container or resets a
desktop checkpoint. It compares remembered Desktop operation IDs and checkpoints
against the pinned database before starting the public relay. Verification
receipts are under `.tools/verification/local-server`.
The local pinned configuration must be established from the verified original
installation, not generated by choosing whichever stack currently owns the port.

`mvp:dev` starts a separate development fixture; it is not the installed server's
restart command. The launcher refuses an origin enrolled in the Desktop profile,
even when the port is free. For new fixtures use independent ports, TLS identity,
credentials and database as described in experimental-development.md. Do not copy
an enrolled identity to a new database at its existing address.

On a history mismatch, reconnect to the original database and server. Preserve
the encrypted local replica and pending edits. Do not erase remembered checkpoints
or silently accept another history. Stopped competing databases remain available
for an explicit recovery comparison if needed.

For an installed unpacked-extension connector refresh, use
`scripts/ops/refresh-local-connector.ps1 -Manifest <registered-manifest.json>
-ReceiptDirectory <new-private-directory>`. It builds the local connector, backs
up the selected installed executable, replaces only that connector and verifies
its SHA-256 hash. Existing native messaging registrations remain intact. Reload
the unpacked extension to use updated popup files.

For an unpacked extension installed outside the checkout, refresh just its popup
using `scripts/ops/refresh-local-extension.ps1 -InstalledDirectory <extension-root>
-ReceiptDirectory <new-private-directory>`. This retains its manifest and browser
identity, backs up the three changed popup files and verifies their hashes.
