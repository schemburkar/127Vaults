# Sunrise workaround review — 2026-10-17

This records what was necessary in the first deployed consumer run, what changed, and what still needs acceptance. Installation data is preserved throughout the upgrade-first follow-up.

| First-run workaround or gap | Change and acceptance status |
| --- | --- |
| Docker Desktop initialization/update stalled on Sunrise | Used Podman with the existing WSL installation. This does not prove a CPU/RAM cause. Prerequisite checks now require actual engine/Compose capabilities; a Docker update is not automatically required. Docker acceptance on another host remains open. |
| The available Compose provider was an unsuitable Docker shim or Python provider | Explicit native Go Compose selection and an `up --no-build` capability preflight. The published flow does not require Python Compose. Native `docker compose up` is retained when the installed provider supports it. |
| Podman's internal-only bridge did not provide usable application ingress | Added a TLS-transparent relay between the internal server network and a separate ingress network. Only the relay publishes the chosen host address. Real isolated Podman relay acceptance passed locally; Sunrise native forwarding must be verified after upgrade. |
| An SSH tunnel supplied both application ingress and Podman VM SSH/API | Test-machine recovery only, not the intended customer installation. Preserve encrypted backups first, then retire application forwarding without losing VM API access. Do not claim native ingress acceptance while this tunnel masks it. |
| Windows account/domain guessing and file permissions failed | Resolve the actual current user's SID via `whoami /user`; use that SID for Windows ACLs. The machine-qualified SSH login is test automation, not a vault account identifier. Workgroup membership is not the logon authority. Linux uses its actual UID/GID and macOS uses native account/Keychain integration. |
| The container's non-root account could not read the TLS key | The restricted TLS helper sets the live directory/key ownership to UID1000 and key mode0600; only the helper gets the capabilities required to do so. Runtime server permissions stay restricted. Fresh local Windows helper/key-read acceptance passed. |
| CA fingerprint wording confused certificate and file hashes | Explicitly label the CA file's SHA-256 separately from the certificate DER fingerprint. Existing Sunrise CA/identity stays unchanged. Do not replace the CA merely to update application binaries. |
| Enrollment opened in a different Edge profile from the extension | Keep the enrollment, trusted server tab and extension in the same consumer profile. Native connector registration points to the intended installed client. Test automation now uses the isolated consumer Edge profile. |
| An already open item showed stale data after a peer sync | Web/desktop refresh the open item after verified sync while protecting a newer selection or unsaved edit. Published upgrade acceptance remains pending. |
| Lock/disconnected local-agent calls could leave the UI waiting | Clear visible secrets before native lock completes; bound local IPC handshake/status/logout and tolerate closed clients. Native package tests pass; installed acceptance remains pending. |
| Current schema8 was refused by old backup tooling | Backup/restore rehearsal accepts schemas1–8; guarded upgrade requires the reviewed current schema8. Identity backup now also preserves license sequence/revocation and clock state. Source guide wording is corrected; one published README sentence still says1–7 and must be refreshed on the next packaging pass. |
| Updating the deployed release could invalidate an activated recipient's download flow | Explicit operator `update-release` issues updated package access while preserving the existing license, installation binding and expiry. Sunrise's update offer passed; the public page hides fresh initialization/activation instructions for that recipient. |
| Setup instructions were one long page | The published seven-stage checklist now supports gated Next/Back, resume, reset and prerequisites before downloads. Live mobile navigation/resume/finish passed. Fresh-host missing-prerequisite/reboot recovery remains an acceptance gate. |
| Operator access disappeared on browser refresh | One-hour signed Secure/HttpOnly/SameSite=Strict cookie, fresh key required for renewal, explicit sign-out. Unit/Worker and live-browser refresh/sign-out checks passed. No operator key is stored in browser storage. |
| Application icons and headers differed from the public site | Canonical public logo and wordmark are applied to desktop, web/PWA, extension, admin and legacy/prototype screens, plus native/PWA/browser icons. Final branded packages are published. |
| A large release verification stream stalled | Deployment tooling now verifies bounded ETag-pinned ranges with full SHA-256 and strict byte counts. Real final publication completed with all37 artifacts verified. |

The remaining near-term work is installed upgrade/preservation acceptance on Sunrise, then a distinct fresh Tailscale setup and two-computer test. Supported setup defaults to loopback; private LAN and Tailscale are explicit choices. A machine administrator can always configure a proxy or change software, so the product must promise safe supported configurations rather than absolute prevention of public hosting. Public Funnel/application routes are outside the selected private-only offering; Cloudflare WARP private routing remains exploratory.

Mac native integration/packaging preparation is committed, but actual builds, signing/notarization and clean-Mac Chrome/desktop acceptance still require a Mac or hosted Mac runner and the appropriate Apple account. No repository has been pushed or created. Request-notification email is a separate follow-up awaiting verified Cloudflare recipient/sender capability; it is not enabled.
