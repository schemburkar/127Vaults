# Public site and commercial onboarding backlog

Updated 2026-10-06. The static site presents plans, a waitlist, and release availability. [Architecture](../architecture/public-access-and-licensing.md) separates commercial contact from vault accounts. No public purchase or artifact is live.

| ID | State | Priority | Outcome and acceptance |
| --- | --- | --- | --- |
| SITE-001 | Experimental implementation; production gate open | P1 | Plan-aware access and waitlist page plus separate encrypted-record intake API exist. Before opening requests publicly, add a reviewed privacy notice, data retention/deletion and key rotation/recovery process, durable abuse controls, email verification or confirmed-contact policy, deployment behind HTTPS at the same origin, backup and operator export tools, and an end-to-end request/withdrawal test. The public form must never create a vault account or request vault credentials. |
| SITE-002 | Catalogue and unavailable page implemented; release gate open | P1 | Publish an immutable signed release catalogue only after each artifact has a reviewed release-specific license, provenance, checksum, detached signature, signing-key instructions, platform support and compatible server version. Verify downloaded bytes and installer/update behavior on a clean machine. Empty catalogue must show no download links. |
| SITE-003 | Open | P1 | Onboard an India-eligible Razorpay merchant account, settle currency/tax/refund/legal terms, then add server-created checkout orders and verified idempotent webhook reconciliation. Never issue a license or cloud installation from a redirect or browser-supplied price. Test paid, failed, duplicate, delayed, refunded, disputed and cancelled events. No live checkout until legal and release gates pass. |
| SITE-004 | Open | P1 | Build a separate customer portal for orders, invoices, renewals, installation binding, replacement license download, and support requests. Use verified customer identity and narrowly scoped authorization. Do not store vault secrets or turn a public-site customer into a self-hosted vault user. Verify ownership transfer and support impersonation controls before launch. |
| SITE-005 | Open | P1 | Cloud sign-up provisions an isolated installation only after payment and operator readiness; owner bootstrap remains a separate secure ceremony. Test failed provisioning, retries, cancellation, isolation, backup, and deletion. Do not offer Cloud checkout before Cloud operations meet the release gate. |
