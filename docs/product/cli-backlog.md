# CLI backlog

## Credential maintenance follow-up — 2026-11-11

Implementation checkpoint for the six CLI security-review items:

1. Owned agent startup credentials now leave scope before the long-lived command loop. Decoded secrets/signing seeds, IPC buffers, session tokens and sync-transport copies have explicit cleanup; usable root keys are cleared before network logout. This is best-effort software memory hygiene, not hardware isolation or a proof about all allocator/OS copies.
2. Local regression coverage includes invalid agent capabilities, authenticated logout, idle expiration and status polling that cannot extend the lease, plus the existing authentication failure, offline, revocation and restart paths.
3. Optional CLI remembered account secrets use OS storage with a protected thirty-day expiry and profile/endpoint/installation/device/account binding. There is an explicit bypass, status and forget command; no plaintext-file fallback. Windows disposable real-store checks pass. The isolated PostgreSQL plus Rust pinned-CA HTTPS enrollment/approval/replay/revocation run also passes.
4. Local encrypted-replica/two-device/replay/conflict regression checks are included in the repeatable CLI gate. Physical-terminal and clean-machine Windows/Linux/keyring acceptance remains open; source tests do not close it.
5. Fresh online password/account-secret rotation uses the existing signed server ceremony, rewraps the existing root and atomically replaces account settings. An encrypted/public recovery journal preserves the previous profile on ambiguous replies; resume/abort require server-confirmed credentials. Replacement-client recovery uses normal enrollment/approval on a fresh profile. This does not implement selected-admin or lost-encryption-credential recovery from ADR-0003.
6. The CLI guide now separates plaintext metadata, encrypted local content, OS-protected credentials, unlocked memory and intentional secret output, and describes the software/device-binding limits.

These changes are not yet in published packages. Keep the wider acceptance requirements below; earlier row descriptions are historical where they still describe rotation/caching as unimplemented.
