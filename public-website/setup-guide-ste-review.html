SELF-HOSTED SETUP

Connect each trusted device.

Use this guide to set up your private server and connect your devices. Your Manage account gives you access to orders and downloads. Create your vault account on your private server.

Setup guide

Your place is saved in this browser. No passwords or server details are saved.

1. Check your computer

Use a Windows or Linux x64 computer with several GB of free disk space. Keep at least 2 GiB available for the container virtual machine. macOS packages are not available yet. Windows 10 requires a supervised trial.

Install Node.js 24

Download Node.js 24, then run the command below. The version number must start with v24.

node --version

Install and start a container engine

Install Podman Desktop and start its Podman machine.

Open Settings → Resources → Compose → Setup and follow the prompts to install the Compose binary. The Compose extension can be active even when the Compose program is not installed. Compose setup instructions.

podman info
podman compose version
podman compose ls
Using only the Podman CLI?

Install the standalone Docker Compose program. Podman uses this program to run Compose commands. You do not need Docker Desktop.

On Windows:

winget install --exact --id Docker.DockerCompose --source winget

After installation, open a new terminal and make sure your Podman machine is running. Run these commands:

docker-compose version
podman compose version
podman compose ls

The first two commands should report the same Compose provider. For Linux or manual installation, follow the standalone Compose instructions and put the binary on your PATH. If Podman selects another provider, set PODMAN_COMPOSE_PROVIDER to the native binary's full path; see Podman's provider configuration.

Using Docker Desktop instead?

Install Docker Desktop, start it, and check:

docker info
docker compose ls

Add --docker to the installer commands in the following steps.

Windows: check WSL 2 and virtualization

Enable hardware virtualization and install or update WSL 2. Approve elevation and complete any requested restart.

wsl --version

If a command fails, complete the software installation and any required restart before you continue.

2. Download and verify

If you have purchased a license, open Manage account to find your downloads. For a trial, request access and use your approved trial link. Download the server package and the clients you need.

Check the downloaded file

Replace FILE with the path to your downloaded file. Compare the SHA-256 result with the checksum on your download page. The values must match.

Windows PowerShell:

Get-FileHash FILE -Algorithm SHA256
Linux
sha256sum FILE

Extract the server package

Open a terminal in the extracted folder, then run:

node install.mjs verify
node install.mjs doctor

The doctor command should report that the package is ready. If verification fails, download the package again. Do not edit the manifest to bypass verification.

3. Start your server

Set up on this computer

For a new installation, run from the extracted server folder:

node install.mjs setup --endpoint 127.0.0.1

Check the server and get its ID

node server.mjs install status
node server.mjs install identify

Save the installation ID and the exact HTTPS address. You will need both in the following steps.

Connect over your private Tailscale network

For a new server installation, install and sign in to Tailscale on the server and each connecting computer. Instead of the loopback setup command above, run:

node install.mjs setup --tailscale

Setup discovers the server's Tailscale IPv4 address automatically. The application still listens only on 127.0.0.1:12780; Tailscale Serve forwards encrypted connections from your private Tailscale network. Serve is part of the Tailscale client, so no separate Tailscale server is required. Setup stops if Funnel is enabled or an existing Serve route conflicts with this connection.

Use the exact HTTPS address reported by setup, such as https://100.64.0.10:12780, replacing the example with your server's address. Tailscale access rules must permit the connection. For browser access, independently verify and trust the server's public CA on each computer; resolve certificate warnings before signing in. Desktop and CLI can discover the server by its Tailscale device name, but still require the installation ID, verified CA and device approval.

Existing loopback installation? A package upgrade preserves its address and does not enable Tailscale access. To change that address, you must preserve the installation identity and database, renew the certificate and reconnect the clients. An automatic migration procedure is not available yet. Do not run setup as a new installation to change an existing server.

Private LAN and other network options

Loopback works on the server computer only. For a new intranet installation, use node install.mjs setup --endpoint 192.168.1.50, replacing the example with the server's actual private LAN IPv4 address. Restrict its host firewall to approved clients or subnets and establish HTTPS trust on each client. Do not use public port forwarding, wildcard listeners or Tailscale Funnel.

Backups and ongoing maintenance

On the server computer, open the extracted server bundle and run node install.mjs maintain. The menu guides you through daily encrypted backups, a test restore, certificate renewal, update previews and restoration into a new installation. Each backup includes the database and installation identity. Keep the recovery key separate from backups and keep a safe copy off the server. Check Server administration → Backups regularly. After installation, complete the backup checks and connect your devices.

Upgrading or fixing startup

Back up first. Keep the original installation identity, project, database volume and license. Do not initialize a replacement or overwrite configuration. If startup fails, run the doctor command and read the local container logs. After restarting the server, run the status command again.

4. Install your license

Open your order in Manage account and enter your server installation ID to get its license. If you have an approved trial, use your trial activation link instead. Confirming trial activation starts the ten-day trial.

Download your license

Save it as license.json in the server folder, then run:

node server.mjs install license --file license.json
node install.mjs start
node server.mjs install status

Make sure the status shows an active license and the correct user limit.

Already activated?

Keep the existing license when upgrading. Do not activate another installation to fix a restart. If you see a binding or signature error, make sure the license belongs to this installation.

5. Create your owner account

Trust the private HTTPS certificate

Do this on each computer that uses the web vault or installed web app. You can sometimes sign in online while a certificate warning prevents the app from preparing its offline files. If the address bar says “Not secure,” correct the certificate trust before continuing. Do not bypass the warning. Importing a connection file into Desktop does not add the certificate to your browser.

Let the Windows combined installer help

If your installer offers Browser HTTPS trust, review the exact server address and public CA file fingerprint. Confirm the fingerprint with your administrator through a trusted channel. Then choose whether to add that CA to your Windows user’s trusted root certificates. Before adding trust, the installer checks the file fingerprint, the CA certificate’s purpose and validity, and the server’s HTTPS connection. This step is optional and is skipped unless you approve it separately. Accepting the installation plan or using --yes does not approve a root certificate.

The change applies to your Windows user’s trusted root store, not only to one server URL. Trust this CA only if you trust its administrator. The installer does not add machine-wide trust, change managed browser policy, or disable certificate validation. Windows or your organization may require approval. Restart your browser, reopen the exact server address, and confirm that the certificate warning is gone before relying on installed/offline web access. Linux uses the browser-specific steps below.

Server administrators: open Server administration → Connect devices → Download public CA and fingerprint. Share only the public certificate and connection file. Confirm the SHA-256 file hash through a trusted channel. The connection file installs trust in Desktop or CLI only; it does not modify browser or operating-system trust.

Windows: Edge and Chrome
  1. Confirm the CA file hash with your administrator using Get-FileHash .\127vaults-public-ca.crt -Algorithm SHA256.
  2. Open the certificate, choose Install Certificate → Current User → Place all certificates in the following store → Trusted Root Certification Authorities. Review the certificate and explicitly accept only your verified CA.
  3. Restart the browser and open the exact HTTPS server address supplied by your administrator. Stop if a certificate warning remains.

This authorizes the CA for your Windows user. Your organization may require an administrator or managed policy instead. Do not change the server address to bypass a hostname mismatch.

Linux: Chrome, Chromium and Firefox

Verify the exact PEM file hash with sha256sum 127vaults-public-ca.crt. In the browser certificate settings, open Authorities and import the verified CA for identifying websites. Firefox may use a separate certificate store; import it there if required. Chromium certificate management differs by distribution and managed policy; use the browser’s certificate manager or your administrator’s approved OS-trust procedure. Restart the browser and open the exact HTTPS address. Do not disable certificate validation or launch with ignore-certificate-errors.

Future macOS clients

The same public connection file is portable. Browser trust is separate: after verifying its file hash with shasum -a 256, import the verified public CA into your login Keychain and explicitly review its trust for SSL. Follow your organization’s managed certificate procedure where applicable. macOS Desktop distribution will be documented when available.

Once the web vault opens without a certificate warning, choose Joining and connection help → Check this browser connection. You may instead approve Desktop’s one-time device code from an already trusted browser or device; that does not require importing the CA into the new computer’s browser.

Confirm the server operator’s public CA fingerprint independently before installing browser or OS trust. Open the exact private HTTPS address; resolve certificate warnings before continuing.

Where is the certificate?

Use the public CA path printed by your installer or download it from Server administration → Connect devices. In manual server installations it is <VAULTS_TLS_DIR>/ca/ca.crt. Never share ca.key. Desktop and CLI use the SHA-256 hash of the complete CA file. A certificate viewer’s DER fingerprint can have a different value.

Verify success or remove browser trust later

After restarting the browser, open the exact HTTPS server address and confirm there is no certificate warning. Then reopen the app so it can prepare its offline files. Unlock and sync online once to prepare your offline vault data. If trust is still refused, check the hostname, certificate dates and your organization’s policy. Do not use an ignore-certificate-errors flag.

On Windows, open certmgr.msc → Trusted Root Certification Authorities → Certificates for the current user to inspect the imported CA. To remove trust later, identify that exact CA carefully and remove only its entry. Do not delete other roots or server identity files. Removing browser trust does not erase vault data but prevents trusted browser connections until trust is restored. Firefox and managed browsers may have separate policy requirements.

Create the first owner

On the server computer, run:

node server.mjs install bootstrap

Open the server’s web page and enter the one-time code. Follow the instructions to create your owner account. Keep your account secret and master password private. Your Manage account email does not create a vault account.

6. Connect your clients

Desktop: share one server connection file

Server administrator: open your local Server administration → Connect devices → Share server connection screen and choose Download connection file. Send the .127vaults-server file to your users through a trusted channel, such as Signal, WhatsApp or email. Use a private-network or Tailscale address that your users can reach. A loopback address works only on the server computer.

Person installing Desktop: install the Windows or Linux desktop client normally. You do not need the combined installer. On the setup screen choose Connect to your private server → Import server connection, select the shared file, check the server name and address, then choose Verify and connect. The file fills in the connection details and public certificate for you.

The same connection file works on all supported desktop platforms. Import it only if you trust the administrator who sent it. It contains public connection details and does not give access to an account or vault. If you are a new user, first use your administrator’s account invitation to create your account. Then choose I already have an account → Register this desktop and enter your vault username.

Using an older desktop client or entering details manually?

Open the manual connection option and enter the exact server HTTPS address, installation ID, public CA certificate path and SHA-256 of the CA file bytes provided by your administrator. Verify and save server trust before registering the desktop. Never share the CA private key.

In an unlocked web app with a trusted server connection, open Settings → Devices → Register a device and approve the code shown by Desktop. This can be a browser session on the same computer. Importing the connection file trusts the server inside Desktop; it does not install a browser or OS root certificate. If you open the web vault on this new computer, first complete the browser certificate-trust step above. Unlock the desktop online once to prepare its offline copy.

Connect the CLI

Replace the placeholders with your server details:

127vaults server trust --url https://PRIVATE-IP:12780 --ca ca.crt --server-id INSTALLATION-ID
127vaults login USERNAME --enroll

Approve its code from a trusted client. On Windows, use your signed-in session for credential storage.

Connect the browser extension

Load the approved extension package and register its packaged native connector. Unlock Desktop or CLI. If you use a vault tab as the source, open the extension in the same browser profile.

Open a website’s sign-in page, click the extension and select the source and matching login. Choose to fill the fields when you are ready. The extension does not submit the form.

7. Try it and back up

Try a test login

  1. Create a vault and a sample login.
  2. Edit the sample login on one client and sync it. Open another client and confirm that the change appears.
  3. Unlock an installed client offline and edit the test login.
  4. Reconnect, sync and confirm that no changes are waiting to sync.

Ordinary browser tabs need the server online.

Keep a recoverable backup

Setup shows your backup key, backup folder and saved recovery settings under ~/.127vaults/ in your home directory. Updates reuse the saved key. Back up the database with its matching installation identity, keep a safe copy of the key separately, and test a restore before relying on the installation. Older backups still require their original key.

License and invitations

Normal license expiry starts a 30-day read-only period. A locked or revoked license can block vault reads and writes. Check the license status if the server reports a license problem or clock rollback. Your encrypted data is retained. Keep any pending edits safe while you resolve the problem.

node server.mjs install status

Before inviting another user, make sure outgoing email is configured and your license has an available user seat.

You reached the end of setup. Keep your private backup and recovery material safe.
