Setup guide

This browser saves your place in this review. It does not save passwords or server details.

1. Prepare your computer

Select your task

  • New server: start with this step.
  • Join a server: go to Step 6.
  • Existing server: use the update instructions in Step 3.

Your Manage account controls orders and downloads. Your vault account is on your private server.

An order access code does not create a vault account.

Use the combined installer

The combined installer guides server setup and client installation.

If you use the combined installer, follow its instructions for required software.

The commands below are for manual setup.

Use a Windows or Linux x64 computer. Make sure that several GB of disk space are available.

Keep at least 2 GiB available for the container virtual machine.

macOS packages are not available. Windows 10 requires a supervised trial.

Manual setup: install Node.js 24
  1. Download Node.js 24.
  2. Install Node.js 24.
  3. Run this command.
node --version

Make sure that the version starts with v24.

Manual setup: install Podman Desktop and Compose
  1. Install Podman Desktop.
  2. Start the Podman machine.
  3. Open Settings → Resources → Compose → Setup.
  4. Follow the instructions to install the Compose binary.
  5. Run these commands.
podman info
podman compose version
podman compose ls

An active extension does not show that the Compose binary is installed.

For more information, read the Compose setup instructions.

Manual setup: use the Podman CLI

Podman can use the native Docker Compose binary. Docker Desktop is not necessary for this configuration.

On Windows, run this command.

winget install --exact --id Docker.DockerCompose --source winget
  1. Open a new terminal.
  2. Start the Podman machine.
  3. Run these commands.
docker-compose version
podman compose version
podman compose ls

Make sure that the two version commands identify the same Compose provider.

For Linux, follow the standalone Compose instructions.

Put the binary on your PATH.

If Podman selects a different provider, set PODMAN_COMPOSE_PROVIDER to the correct binary's full path.

Refer to Podman's provider configuration.

Manual setup: use Docker Desktop
  1. Install Docker Desktop.
  2. Start Docker Desktop.
  3. Run these commands.
docker info
docker compose ls

For Docker, add --docker to the server installer commands in this guide.

Windows: prepare WSL 2
  1. Enable hardware virtualization.
  2. Install or update WSL 2.
  3. Approve the required administrator prompt.
  4. Restart Windows if instructed.
  5. Run this command.
wsl --version

If a command fails, correct the problem before you continue.

2. Get the packages

Get your download link

  • Paid plan: open your order in Manage account.
  • Trial: request access.
  • Joining user: get a client-download link from your server operator.

Download the applicable installer or packages from your approved download page.

Joining users do not need the purchaser's account or server license.

Compare the file hash

  1. Find the SHA-256 value on your download page.
  2. Replace FILE with the downloaded file's path.
  3. Run the applicable command below.
  4. Compare the result with the download page.

Windows PowerShell:

Get-FileHash FILE -Algorithm SHA256
Linux
sha256sum FILE

If the values are different, do not run the file.

Download the file again.

Manual setup: extract and verify the server package
  1. Extract the server package.
  2. Open a terminal in the extracted folder.
  3. Run these commands.
node install.mjs verify
node install.mjs doctor

Make sure that doctor reports ready.

If verification fails, download the package again.

Do not change the manifest to bypass verification.

3. Start the server

Existing installation: use the update procedure below. Do not start a new installation to repair an existing server.

Use the combined installer

  1. Run the approved combined installer.
  2. Select the server setup role.
  3. Select the components you need.
  4. Follow the setup instructions.
  5. Keep the server address shown by the installer.
Manual setup: use this computer only

Use this procedure only for a new installation.

In the extracted server folder, run this command.

node install.mjs setup --endpoint 127.0.0.1

The address 127.0.0.1 works only on the server computer.

Manual setup: read the server status and installation ID 
node server.mjs install status
node server.mjs install identify

Keep the installation ID and the exact HTTPS address.

New server: use Tailscale
  1. Install Tailscale on the server.
  2. Sign in to Tailscale.
  3. Install Tailscale on each computer that will connect.
  4. Sign in to the same permitted private network on those computers.

For manual setup, use this command instead of the same-computer setup command.

node install.mjs setup --tailscale

Setup finds the server's Tailscale IPv4 address.

The application listens on 127.0.0.1:12780. Tailscale Serve forwards connections from the private network.

Tailscale Serve is part of the Tailscale client. A separate Tailscale server is not necessary.

Setup refuses Funnel and conflicting Serve routes.

  1. Use the exact HTTPS address shown by setup.
  2. Make sure that Tailscale access rules permit the connection.
  3. Complete browser certificate trust on each computer that uses the web app.

An example address is https://100.64.0.10:12780. Use your server's address, not this example.

Desktop and CLI can find a server by its Tailscale name.

They still need the installation ID, verified CA certificate and device approval.

New server: use a private LAN

For manual setup, replace the example with the server's private LAN IPv4 address.

node install.mjs setup --endpoint 192.168.1.50
  1. Restrict the host firewall to permitted computers or subnets.
  2. Complete HTTPS certificate trust on each computer that uses the web app.

Do not use public port forwarding, wildcard listeners or Tailscale Funnel.

This procedure does not enable Cloudflare private routing.

Existing server: update or repair
  1. Make a backup before the update.
  2. Keep the original installation identity, project, database volume and license.
  3. Use the backed-up update procedure.
  4. If startup fails, run doctor.
  5. Read the local container logs.
  6. After a restart, read the server status again.

Do not overwrite the configuration or create a replacement installation.

A package update does not change a same-computer installation into a Tailscale installation.

A network change requires a separate migration procedure.

That procedure must preserve the identity and database.

It can also require certificate renewal and client reconnection.

Do not repeat new-server setup to change an existing address.

Server maintenance

On the server computer, open a terminal in the extracted server folder.

node install.mjs maintain

The menu provides backup scheduling, restore tests, certificate renewal, update preview and restoration to a new installation.

Keep the recovery key separate from the backup files.

Keep a safe copy of the key on another device.

Regularly read Server administration → Backups.

Installed packages do not show that backups and device setup are complete.

4. Install the license

The server needs a signed license for its installation.

Use the combined installer

Use the setup link for the applicable order.

The installer guides installation binding and license setup.

If the installer reports an active license, continue to Step 5.

Trial setup
  1. Open your approved private trial page.
  2. Enter the installation ID when requested.
  3. Confirm activation.

Trial activation starts the ten-day trial period.

Paid Personal setup

Use your paid order in Manage account.

Do not use trial activation to repair a paid installation.

Use the license and setup access for the applicable paid order.

Manual setup: install the license file
  1. Download the license for this installation.
  2. Save the file as license.json in the server folder.
  3. Run these commands.
node server.mjs install license --file license.json
node install.mjs start
node server.mjs install status

Make sure that the status shows an active license and the correct user limit.

Existing license or license error

Keep the existing license during an update.

Do not activate a different installation to repair startup.

If a binding or signature error occurs, obtain the matching license.

5. Create the owner account

The local operator account and vault owner account are different accounts.

A public contact email does not create a vault account.

First, set browser certificate trust

Do this on each computer that uses the web vault or installed web app.

Desktop's connection file sets trust inside Desktop. It does not set browser trust.

An online login does not show that the offline app is ready.

If the address bar shows “Not secure,” stop before you continue setup.

Do not bypass the certificate warning.

Get the public CA certificate

The server operator can use the public CA path shown by the installer.

The operator can also use Server administration → Connect devices → Download public CA and fingerprint.

In manual installations, the file is <VAULTS_TLS_DIR>/ca/ca.crt.

Only share the public certificate and public connection file.

Do not share ca.key or another private key.

Confirm the exact CA file SHA-256 with the operator through a trusted channel.

A certificate viewer can show a different fingerprint. This guide uses the SHA-256 of the complete PEM file.

Windows: use the installer's browser trust step

If the installer offers Browser HTTPS trust, use this procedure.

  1. Read the server address and public CA file fingerprint.
  2. Confirm the fingerprint through your trusted operator or channel.
  3. Read the Windows trust explanation.
  4. If you agree, select the separate trust confirmation.
  5. Approve a Windows prompt only for this verified CA.

The installer verifies the file, CA signing purpose, validity and server HTTPS connection.

This step is optional. Its default is to skip the import.

The general install confirmation and --yes do not approve CA import.

The CA enters the current Windows user's trusted root store.

This trust applies beyond one server URL. Only trust a CA controlled by an operator you trust.

The installer does not change machine-wide trust or managed browser policy.

Your organization can require IT approval.

Windows: import the CA manually
  1. Replace the example filename if your public CA file has a different name.
  2. Run this command.
Get-FileHash .\127vaults-public-ca.crt -Algorithm SHA256
  1. Compare the result with the operator's file hash.
  2. Open the verified certificate file.
  3. Select Install Certificate.
  4. Select Current User.
  5. Select Place all certificates in the following store.
  6. Select Trusted Root Certification Authorities.
  7. Review the certificate.
  8. Confirm the import only if it is the verified CA.

This changes trust for your Windows user. An organization policy can prevent the change.

Do not change the server address to bypass a hostname mismatch.

Linux: import the CA in your browser
  1. Run this command for the public CA file.
sha256sum 127vaults-public-ca.crt
  1. Compare the result with the operator's file hash.
  2. Open the browser's certificate settings.
  3. Open Authorities.
  4. Import the verified CA for website identification.

Firefox can use a separate certificate store.

Chromium certificate settings depend on the Linux distribution and managed policy.

If import is unavailable, ask your administrator for the approved trust procedure.

Do not disable certificate validation or use an ignore-certificate-errors flag.

macOS: reference instructions for future clients

macOS Desktop packages are not available.

The public connection file is portable. Browser trust is a separate setting.

  1. Use shasum -a 256 to calculate the public CA file hash.
  2. Compare the result with the operator's file hash.
  3. Import the verified public CA into your login Keychain.
  4. Review its SSL trust setting.

Follow your organization's managed certificate procedure when applicable.

Verify browser trust

  1. Restart the browser.
  2. Open the exact HTTPS server address.
  3. Make sure that there is no certificate warning.

If a warning remains, inspect the hostname, certificate dates and organization policy.

After trust is correct, reopen the app to prepare its offline files.

An offline vault copy also needs an online unlock and sync.

If available, select Joining and connection help → Check this browser connection.

Remove browser trust later
  1. On Windows, open certmgr.msc.
  2. Open Trusted Root Certification Authorities → Certificates for the current user.
  3. Identify the exact imported CA.
  4. Remove only that certificate entry.

Do not delete other root certificates or server identity files.

Removal does not erase vault data. The browser will refuse trusted connections until certificate trust is restored.

Firefox and managed browsers can have separate policy requirements.

Create the first vault owner

If an owner already exists, use the existing account.

For a new server, use the first-owner setup link shown by the installer.

Manual setup: get a first-owner code

On the server computer, run this command.

node server.mjs install bootstrap

Enter the one-time code in the server's web screen.

Follow the account creation steps on the private server.

Keep your account secret and master password private.

6. Connect a device

Use this step if you join an existing server.

You do not need to install a server or obtain the purchaser's license.

Server operator: send the joining information

  1. Open Server administration → Connect devices → Share server connection.
  2. Select Download connection file.
  3. Send the .127vaults-server file through a trusted channel.
  4. Send the protected client-download link.
  5. For a new account, send an account invitation.

You can use Signal, WhatsApp or email to share the information.

Use a reachable private-network or Tailscale address.

A loopback address works only on the server computer.

Understand the three different steps
  • Connection file: identifies the server and its public certificate. It does not give account or vault access.
  • Account invitation: permits a new user to create a vault account.
  • Device approval: permits that user's device after verification of its code and details.

The same connection file works on supported Desktop platforms.

Joining user: connect Desktop

  1. Get the approved Windows or Linux Desktop package.
  2. Install Desktop.
  3. Open Connect to your private server → Import server connection.
  4. Select the operator's connection file.
  5. Verify the server name and address with the operator.
  6. Select Verify and connect.

The file supplies the connection details and public certificate.

Only import a file from your trusted operator.

The combined installer is an alternative to the separate Desktop installer.

New user: create your account first
  1. Complete browser certificate trust on the computer that will open the invitation.
  2. Open your account invitation.
  3. Complete account registration on the private server.
  4. Keep the registered browser session available for Desktop approval.

The trusted browser session can be on the same computer as Desktop.

A separate physical device is not always necessary.

Register and approve Desktop

  1. In Desktop, select I already have an account → Register this desktop.
  2. Enter your vault username.
  3. Read the one-time approval code.
  4. In a trusted web session, open Settings → Devices → Register a device.
  5. Compare the code and device details.
  6. If the details agree, approve the device.
  7. Return to Desktop.
  8. Unlock Desktop online once.

The online unlock prepares Desktop's encrypted offline copy.

You can approve Desktop from a trusted browser on this computer or another device.

Desktop import does not install a browser or OS root certificate.

If this computer uses the web vault, complete its separate browser trust procedure.

Older Desktop client: enter connection details manually
  1. Open the manual connection option.
  2. Enter the operator's exact HTTPS address.
  3. Enter the installation ID.
  4. Select the public CA certificate path.
  5. Enter the SHA-256 of the CA file bytes.
  6. Verify and save server trust.
  7. Register Desktop.

Do not share the CA private key.

Connect the CLI

Replace the placeholders with your server details.

127vaults server trust --url https://PRIVATE-IP:12780 --ca ca.crt --server-id INSTALLATION-ID
127vaults login USERNAME --enroll

Approve the code from a trusted client.

On Windows, use your signed-in session for credential storage.

Connect the browser extension
  1. Load the approved extension package.
  2. Register its packaged native connector.
  3. Unlock Desktop or CLI.

For a web-tab source, use the browser profile that contains the unlocked vault tab.

  1. Open the applicable website's sign-in page.
  2. Open the extension.
  3. Select the vault source.
  4. Select the saved login.

The extension fills the form only after your action.

It does not submit the form.

7. Test and back up

Test the connection and sync

  1. Create a vault.
  2. Add a sample login.
  3. Edit the sample login on one client.
  4. Sync that client.
  5. Open the sample login on another client.
  6. Make sure that the change is present.
  7. Disconnect an installed client from the network.
  8. Unlock that client offline.
  9. Edit the sample login.
  10. Connect the client to the network again.
  11. Sync the client.
  12. Make sure that no changes remain pending.

Ordinary browser tabs need the server online.

Prepare a backup that you can restore

Setup shows the backup key location, backup folder and saved recovery settings.

The default recovery settings are under ~/.127vaults/ in your home directory.

Updates use the saved key. Older backups still need their original key.

  1. Back up the database.
  2. Back up its matching installation identity.
  3. Keep a safe copy of the key separate from the backup files.
  4. Test restoration in an isolated installation.
  5. Make sure that restoration succeeds before you depend on the backup.

The operator can use node install.mjs maintain for guided maintenance.

License status and invitations

After normal expiry, the license has a 30-day read-only period.

A locked or revoked license can block vault reads and writes.

A detected clock rollback can also lock access.

The server retains encrypted data. Keep pending local changes during repair.

node server.mjs install status

Before you invite another user, make sure that SMTP and available seats are ready.
