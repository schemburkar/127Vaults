SELF-HOSTED SETUP

Connect each trusted device.

Your public order access code is only for the order page. Vault accounts and devices are created on your private server.

1. Establish server trust

On the server, run node server.mjs install status and node server.mjs install identify. Record the private HTTPS address, installation ID, and CA fingerprint through your operator channel. Copy only the public CA certificate, normally ~/.127vaults-test/ca/ca.crt, to each client. Compare its fingerprint before trusting it. Never copy the CA private key.

Trust the CA in the browser or operating system used for the server web app. Open the exact private HTTPS address printed by the installer. Certificate warnings are a stop condition; correct the endpoint or trust material instead of bypassing them.

2. Create the owner in the server web app

Run node server.mjs install bootstrap locally. Enter that one-time code in the server-hosted setup screen and keep it off the public order page. Save the account secret and recovery material. The public contact email does not automatically become a vault user.

3. Add another computer

For the CLI, run 127vaults server trust --url https://PRIVATE-IP:12780 --ca ca.crt --server-id INSTALLATION-ID, using the exact address and ID from your installation. Then run 127vaults login USERNAME --enroll. In an already trusted web session, open Trusted devices and approve the code shown by the CLI. The CLI verifies the approval before saving its device key.

The current Windows desktop uses a trusted CLI profile or an operator-provided profile. After the trust profile exists, open the desktop, choose “I already have an account,” and approve its one-time code in the server web app. Complete one online unlock to provision its encrypted offline copy. An integrated desktop trust-import screen is still pending.

4. Invite another vault user

The owner sends an invitation from the server web app. The recipient verifies the invited email address and enrolls on that same private server. A signed license reserves seats for outstanding invitations. SMTP must be configured and tested before this step works outside the disposable fixture.

5. Read license state

Active: normal licensed writes. Read-only: the 30-day period after expiry; vault and invitation writes are blocked while sign-in and reads remain available. Locked or revoked: licensed writes remain blocked until a valid replacement license is installed. A detected clock rollback also locks writes until the host clock catches up. Encrypted data is retained.

Check the authoritative state with node server.mjs install status on the server. Online clients can read the server's redacted status; an offline client may have stale information. After renewal, download the new license from the simulated order, run node server.mjs install license --file license.json, restart, and verify status again. Do not discard offline encrypted edits while resolving a license state.

For the extension, connect an already enrolled web, desktop, or CLI source. The extension does not create a vault account or install a license; its experimental flow only fills a selected login after a user action.
