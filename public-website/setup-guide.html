Setup guide

Your place is saved in this browser. No passwords or server details are saved.

1. Check your computer

Use a Windows or Linux x64 computer with several GB of free disk. Allow at least 2 GiB for the container VM. macOS packages are not available yet; Windows 10 remains a supervised trial.

Install Node.js 24

Download Node.js 24, then check the version. It should start with v24.

node --version

Install and start a container engine

Install Podman Desktop and start its Podman machine.

Open Settings → Resources → Compose → Setup and follow the prompts to install the Compose binary. An active built-in extension does not confirm that the binary is installed. Compose setup instructions.

podman info
podman compose version
podman compose ls
Using only the Podman CLI?

Install the standalone native Docker Compose binary. Podman uses it as its Compose provider; Docker Desktop is not required.

On Windows:

winget install --exact --id Docker.DockerCompose --source winget

Open a new terminal after installation. With your Podman machine running, check:

docker-compose version
podman compose version
podman compose ls

The two version commands should identify the same provider. For Linux or manual installation, follow the standalone Compose instructions and put the binary on your PATH. If Podman selects another provider, set PODMAN_COMPOSE_PROVIDER to the native binary's full path; see Podman's provider configuration.

Using Docker Desktop instead?

Install Docker Desktop, start it, and check:

docker info
docker compose ls

Add --docker to the installer commands in the following steps.

Windows: check WSL 2 and virtualization

Enable hardware virtualization and install or update WSL 2. Approve elevation and complete any requested restart.

wsl --version

If a check fails, finish installation or restart before continuing.

2. Download and verify

Request access and download the server and clients from your approved private invitation.

Check the downloaded file

Replace FILE with its path. Compare the SHA-256 with your invitation.

Windows PowerShell:

Get-FileHash FILE -Algorithm SHA256
Linux
sha256sum FILE

Extract the server package

Open a terminal in the extracted folder, then run:

node install.mjs verify
node install.mjs doctor

Doctor should report ready. If verification fails, download again; never edit the manifest to bypass it.

3. Start your server

Set up on this computer

For a new installation, run from the extracted server folder:

node install.mjs setup --endpoint 127.0.0.1

Check the server and get its ID

node server.mjs install status
node server.mjs install identify

Keep the installation ID and exact HTTPS address for the next steps.

Connect over your private Tailscale network

For a new server installation, install and sign in to Tailscale on the server and each connecting computer. Instead of the loopback setup command above, run:

node install.mjs setup --tailscale

Setup discovers the server's Tailscale IPv4 address automatically. The application still listens only on 127.0.0.1:12780; Tailscale Serve forwards encrypted connections from your private Tailscale network. Serve is part of the Tailscale client, so no separate Tailscale server is required. Setup refuses Funnel and conflicting Serve routes.

Use the exact HTTPS address reported by setup, such as https://100.64.0.10:12780, replacing the example with your server's address. Tailscale access rules must permit the connection. For browser access, independently verify and trust the server's public CA on each computer; resolve certificate warnings before signing in. Desktop and CLI can discover the server by its Tailscale device name, but still require the installation ID, verified CA and device approval.

Existing loopback installation? A package upgrade preserves its address and does not enable Tailscale access. Changing that address requires a separately reviewed network migration, including certificate renewal and client reconnection while preserving the installation identity and database. There is no documented automatic migration command yet; do not rerun fresh setup or initialize another installation.

Private LAN and other network options

Loopback works on the server computer only. For a new intranet installation, use node install.mjs setup --endpoint 192.168.1.50, replacing the example with the server's actual private LAN IPv4 address. Restrict its host firewall to approved clients or subnets and establish HTTPS trust on each client. Do not use public port forwarding, wildcard listeners or Tailscale Funnel. Cloudflare private routing remains under review and is not enabled by this setup.

Upgrading or fixing startup

Back up first. Keep the original installation identity, project, database volume and license. Do not initialize a replacement or overwrite configuration. Run doctor and inspect local container logs if startup fails. After a restart, check status again.

4. Activate your trial

Open your private invitation, enter the installation ID and confirm activation. This starts the ten-day trial.

Download your license

Save it as license.json in the server folder, then run:

node server.mjs install license --file license.json
node install.mjs start
node server.mjs install status

Status should show an active license and the expected user limit.

Already activated?

Keep the existing license when upgrading. Do not activate another installation to fix a restart. Binding or signature errors require the matching license.

5. Create your owner account

Trust the private HTTPS certificate

Server administrators: open Server administration → Connect devices → Download public CA and fingerprint. Share only the public certificate and connection file. Confirm the SHA-256 file hash through a trusted channel. The connection file installs trust in Desktop or CLI only; it does not modify browser or operating-system trust.

Windows: Edge and Chrome
  1. Confirm the CA file hash with your administrator using Get-FileHash .\127vaults-public-ca.crt -Algorithm SHA256.
  2. Open the certificate, choose Install Certificate → Current User → Place all certificates in the following store → Trusted Root Certification Authorities. Review the certificate and explicitly accept only your verified CA.
  3. Restart the browser and open the exact HTTPS server address supplied by your administrator. Stop if a certificate warning remains.

This authorizes the CA for your Windows user. Your organization may require an administrator or managed policy instead. Do not change the server address to bypass a hostname mismatch.

Linux: Chrome, Chromium and Firefox

Verify the exact PEM file hash with sha256sum 127vaults-public-ca.crt. In the browser certificate settings, open Authorities and import the verified CA for identifying websites. Firefox may use a separate certificate store; import it there if required. Chromium certificate management differs by distribution and managed policy; use the browser’s certificate manager or your administrator’s approved OS-trust procedure. Restart the browser and open the exact HTTPS address. Do not disable certificate validation or launch with ignore-certificate-errors.

Future macOS clients

The same public connection file is portable. Browser trust is separate: after verifying its file hash with shasum -a 256, import the verified public CA into your login Keychain and explicitly review its trust for SSL. Follow your organization’s managed certificate procedure where applicable. macOS Desktop distribution will be documented when available.

Once the web vault opens without a certificate warning, choose Joining and connection help → Check this browser connection. You may instead approve Desktop’s one-time device code from an already trusted browser or device; that does not require importing the CA into the new computer’s browser.

Confirm the server operator’s public CA fingerprint independently before installing browser or OS trust. Open the exact private HTTPS address; resolve certificate warnings before continuing.

Where is the certificate?

The public certificate is normally ~/.127vaults-test/ca/ca.crt. Never share ca.key. Desktop and CLI use the SHA-256 of the CA file bytes, which differs from a certificate DER fingerprint.

Create the first owner

Run locally on the server:

node server.mjs install bootstrap

Enter the one-time code in the server’s web screen. Save your account secret and master password privately. Your public contact email does not create a vault account.

6. Connect your clients

Desktop: share one server connection file

Server administrator: open your local Server administration → Connect devices → Share server connection screen and choose Download connection file. Send the .127vaults-server file to your users through a trusted channel, such as Signal, WhatsApp or email. Use a reachable private-network or Tailscale server address; a loopback address works only on the server computer.

Person installing Desktop: install the Windows or Linux desktop client normally. You do not need the combined installer. On the setup screen choose Connect to your private server → Import server connection, select the shared file, check the server name and address, then choose Verify and connect. The file fills in the connection details and public certificate for you.

The same connection file works across supported desktop platforms. Only import files from your administrator. The file contains public connection information and grants no account or vault access. New users still need an account invitation from their server administrator. Then choose I already have an account → Register this desktop and enter your vault username.

Using an older desktop client or entering details manually?

Open the manual connection option and enter the exact server HTTPS address, installation ID, public CA certificate path and SHA-256 of the CA file bytes provided by your administrator. Verify and save server trust before registering the desktop. Never share the CA private key.

In the unlocked web app on an already trusted device, open Settings → Devices → Register a device and approve its code. Importing the connection file trusts the server inside Desktop; it does not install a browser or OS root certificate. If you open the web vault on this new computer, first complete the browser certificate-trust step above. Unlock the desktop online once to prepare its offline copy.

Connect the CLI

Replace the placeholders with your server details:

127vaults server trust --url https://PRIVATE-IP:12780 --ca ca.crt --server-id INSTALLATION-ID
127vaults login USERNAME --enroll

Approve its code from a trusted client. On Windows, use your signed-in session for credential storage.

Connect the browser extension

Load the approved extension package and register its packaged native connector. Unlock desktop or CLI. For a web-tab source, use the same browser profile as the unlocked vault tab.

Open a matching sign-in page, click the extension and choose the source and login. Filling requires your action and never submits the form.

7. Try it and back up

Try a test login

  1. Create a vault and a sample login.
  2. Edit it on one client, sync, and check another.
  3. Unlock an installed client offline and edit the test login.
  4. Reconnect and confirm there are no pending changes.

Ordinary browser tabs need the server online.

Keep a recoverable backup

Setup shows your backup key, backup folder and saved recovery settings under ~/.127vaults/ in your home directory. Updates reuse the saved key. Back up the database with its matching installation identity, keep a safe copy of the key separately, and test a restore before relying on the installation. Older backups still require their original key.

License and invitations

Expiry starts a 30-day read-only period. Locked/revoked licenses or detected clock rollback block licensed writes; reads, sign-in and recovery remain available. Encrypted data is retained. Preserve pending edits during repair.

node server.mjs install status

Check SMTP and available seats before inviting another user.

You reached the end of setup. Keep your private backup and recovery material safe.
