Opening your invitation…

1. Choose your packages

Install the server once, then connect Desktop, CLI or the extension from your trusted computers. Downloads are private experimental builds and are not publicly signed releases.

2. Prepare your server

Extract the server archive. Install Node.js 24 and Podman or Docker with Compose on the server machine. From the extracted folder, run:

node install.mjs doctor
node server.mjs install init
node server.mjs install start
node server.mjs install identify

Windows with Podman: install Podman and Podman Desktop, start a Podman machine, and set up native Compose in Podman Desktop. Verify podman compose version. Python is not required. To select a specific native Compose executable, add --compose-provider "C:/full/path/docker-compose.exe" to doctor and each server command that uses Compose, including start, identify, license, status and bootstrap. The doctor reports missing prerequisites. Docker: add --docker to doctor and every server command.

For another computer to connect, add --endpoint 192.168.1.50 to init, replacing the example with the server’s actual private IPv4 address. See the included README for network options. Keep the server private; do not forward it to the public Internet.

Copy only the installation UUID printed by identify below. Never enter a bootstrap code, account secret, password or private key on this website.

3. Install the license and connect

Save the license in the extracted server folder, then run:

node server.mjs install license --file trial-license.json
node server.mjs install start
node server.mjs install status
node server.mjs install bootstrap

The server bundle already pins the issuer’s public key. Create your vault owner on your server’s HTTPS web app using its local bootstrap code. Your request email is not a vault account.

On another computer, verify and trust the server’s public CA certificate and use its exact HTTPS address and installation ID. Approve new Desktop or CLI devices from an already trusted session. The extension connects to an unlocked web, Desktop or CLI source.

Follow the client setup guide

Your license allows 10 days of server writes, followed by the existing 30-day read-only period. Encrypted data is retained. Offline clients may queue edits that the expired server refuses. Contact your inviter to continue; downloading again never restarts the trial.

Upgrade your existing installation

Keep the existing database volume, private identity and license. Extract the updated server into a new folder. Do not run initialization or activate another installation.

Keep a protected 32-byte backup key separately from your backups. Create one locally if needed with node server.mjs database keygen --output ABSOLUTE-KEY-PATH. From the new extracted folder, run:

node install.mjs upgrade --from OLD-SERVER-FOLDER --backup-dir NEW-BACKUP-FOLDER --backup-key-file ABSOLUTE-KEY-PATH

Add --docker for Docker, or --compose-provider FULL-NATIVE-COMPOSE-PATH to select Podman's native provider. The upgrader stops writes, takes and rehearses an encrypted backup, preserves configuration, and starts the new package. Current schema 8 is supported; older schemas require a reviewed migration. If backup fails, the old server is restarted. If startup fails, preserve both folders and inspect the error before retrying. Never delete the database volume or keys.

Update Desktop at its existing location. Keep the CLI profile and native connector path stable, and reload the extension from its stable installed folder. Verify the existing vault and queued changes after reconnecting. Your trial expiry is unchanged.
