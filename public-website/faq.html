QUESTIONS & ANSWERS

The practical details.

Answers to the questions that matter when choosing how to run 127Vaults.

01 / HOSTING

Where does my data live?

With Self-Hosted, the server and its encrypted vault data live on infrastructure you operate. With planned 127Vaults Cloud, 127Vaults would operate the server. Authorized devices also retain encrypted local copies of vaults they can access.

02 / OFFLINE ACCESS

What happens if my server goes offline?

Devices with a complete encrypted local copy can continue using their downloaded vaults. Synchronization and actions that require the server remain unavailable until it returns.

A local copy does not replace a backup. Protect your server backups and retain your account recovery material.

03 / PRIVACY

Can another user read my vault?

No. Each user has their own private vaults; other users cannot read them, and public links are not part of the product.

04 / LICENSING

How do major versions work?

Personal Self-Hosted licenses include five users and cover the purchased major version. Additional users can be enabled by request at no extra charge. Moving to a later major version is optional and separately licensed. Commercial Self-Hosted contracts include releases made during the active contract.

05 / SECURITY

Does Cloud use different encryption?

No. Personal, Commercial, and Cloud share the same core security design. Cloud pricing covers managed infrastructure, not stronger encryption.

06 / SELF-HOSTING

What does “self-hosted” mean?

You run the 127Vaults server and its database on infrastructure you control. The server stores encrypted vault records and synchronization history so your authorized devices can exchange changes.

You manage the server’s availability, updates, network access and backups. The web client is served by your server; desktop, CLI and browser extension clients are installed separately.

07 / NETWORK ACCESS

Can I expose my server directly to the internet?

Direct public internet deployment is not currently supported. Use localhost, a private LAN, or the supported private Tailscale setup. Public reverse proxies, custom domains and Tailscale Funnel are not supported.

Tailscale lets permitted devices reach your server remotely through a private network. Users must still sign in and complete device approval. See the server setup guide.

08 / OFFLINE ACCESS

What does “offline-first” mean?

After an authorized device has synchronized a complete encrypted vault copy, supported clients can unlock, read and edit that copy without a server connection. Changes synchronize when connectivity returns, with conflicting changes presented for review.

Desktop, CLI and the installed web app support offline use. An ordinary browser tab requires a server connection. Initial setup, device enrollment and some account-management actions also require a connection.

09 / ENCRYPTION

What encryption does 127Vaults use?

Vault contents are encrypted on your device using XChaCha20-Poly1305 with 256-bit keys. This provides encryption and detects tampering with authenticated records.

Password-based key derivation uses Argon2id with 64 MiB of memory, 3 passes and 1 lane. HKDF-SHA-256 derives separate keys for different purposes. Your master password and account Secret Key protect a randomly generated root key.

See the security technical details for the full parameters and trust boundaries.

10 / CLIENT COMMUNICATION

How do clients communicate with the server?

Clients connect over HTTPS using TLS 1.2 or TLS 1.3, with certificate validation. Authentication uses OPAQUE, which lets the client prove knowledge of its credentials without sending the master password itself to the server.

Vault contents are encrypted before synchronization and decrypted locally on authorized clients. HTTPS also protects the authentication, synchronization and metadata exchanged over the network.

11 / SERVER STORAGE

What can my server see?

The server stores encrypted vault contents, alongside account, device and synchronization metadata needed to operate the service. It does not receive your master password or plaintext vault contents during normal operation.

This does not provide complete metadata anonymity. Your server and its backups retain encrypted records and must be protected.

12 / TRUST BOUNDARIES

What happens if my server or device is compromised?

A stolen server database contains encrypted vault records rather than plaintext vault contents. Protection still depends on your credentials, the encryption implementation and trusted client software.

The web client loads code from your server. An attacker controlling that server could replace the web code and capture credentials or plaintext when you unlock. Installed clients reduce that particular dependency but still require trusted software and updates.

A compromised, unlocked device can expose secrets as you use them. Encryption cannot protect plaintext from an attacker who controls that device.
